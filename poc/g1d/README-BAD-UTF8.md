# G1d / AC-06 — Invalid UTF-8 SRT negative on real Redmi

**State:** `PROPOSED / HUMAN-RUN ONLY / NOT_EXECUTED`. This is NOT a replacement for already-PASSed G1d missing-file/restore test. Source stack: Draft PR #21 SEL-01 → Draft PR #23 G1d missing-file → this new Draft PR. No change to Android app, source contract, registry, test markers, server or Windows settings.

## Fixture and expected behavior

`G1D-Redmi-BadUtf8-SRT-Test.ps1` generates a small **synthetic** independent SRT: cue `1` with start/end timestamps `00:00:00,000 --> 00:00:02,000` (correct SRT syntax), followed by byte `0xFF` in cue text. This is deliberately invalid UTF-8 despite correct ASCII cue structure. The SEL-01 debug `checkedFileDigest` uses strict UTF-8 decoding (`CodingErrorAction.REPORT`), so app source **predicts** rejection. This is a source-code expectation, not a real-TV proof.

Existing registered media A and C, unregistered media B and D were Human-tested; C had been registered previously. **Select VLC explicitly**: the prior G1d restore false FAIL occurred only because a different player engine was used.

## Script phases (Human executes manually, in sequence)

Save the script from the **exact pinned Draft PR head** into `Downloads\G1D-Redmi-BadUtf8-SRT-Test.ps1` and review it first.

```powershell
$g1dUtf8 = "$env:USERPROFILE\Downloads\G1D-Redmi-BadUtf8-SRT-Test.ps1"
& $g1dUtf8 -Phase Preflight
```

**Expected:** `G1D_UTF8_REDMI_MATCH`, `G1D_UTF8_BASELINE_PASS`, `G1D_UTF8_PREFLIGHT_READ_ONLY_PASS`. STOP on any mismatch. Nothing is modified in Preflight.

Only after Human verifies preflight, **close VLC player** (not uninstall). Supply the path to the previously audited SEL-01 ARM32 APK; if the old PowerShell session has disappeared, do not reuse an undefined `$apks` variable.

```powershell
$sel01Apk = 'FULL_ABSOLUTE_PATH_TO_PREVIOUSLY_AUDITED_APP_ARMEABI_V7A_DEBUG_APK'
& $g1dUtf8 -Phase StageBadUtf8 -ApkPath $sel01Apk
```

Type `STAGE G1D BAD UTF8` when prompted. The script checks local APK hash, the target and original SHA256; writes an invalid temporary fixture in Windows TEMP and TV shell-temp; renames *only* original SRT to the protected app-private UTF8 backup; `run-as cp` puts the synthetic fixture in the original pathname; checks both SHA256s. A failed `run-as cp` (including a possible device-dependent SELinux restriction) is **BLOCKED, not PASS** — protected original remains in backup; run Restore. Script/device runtime is **not yet tested**.

Expect `G1D_UTF8_FIXTURE_STAGED` and/or `G1D_UTF8_STAGED_HASH_PASS_NOT_TV_PASS`. Open **previously registered video A with VLC in a fresh player session**; expect exact `P1 G1c - Saved SRT` **absent**, video+audio normal and no crash. If the fixture is rejected, built-in or other media subtitles may still exist; don't confuse them with G1c.

Optional read-only state check while staged:

```powershell

```

**Always restore immediately after test or on failure; close the VLC player first:**

```powershell

```

Type `RESTORE G1D UTF8`. Restore works **without APK path**; requires original backup exact SHA and either missing synthetic SRT or exactly matching synthetic SRT. If present, the exact synthetic file is moved to a distinct discard filename; then the protected original is renamed back and SHA verified. **Only after** verifying original, the exact temporary test file is deleted. Backup is not deleted by a cleanup command. If STOP, **do not edit/delete files**, don't call `pm clear`, uninstall, copy over SRT or reset registry.

```powershell
& $g1dUtf8 -Phase VerifyRestored
```

Expect `G1D_UTF8_ORIGINAL_SRT_RESTORED_HASH_PASS` and `G1D_UTF8_RESTORED_BASELINE_READ_ONLY_PASS_NOT_TV_PASS`. Open A again via **VLC** without registration: G1c track should return; existing ON preference and two distinct Vietnamese cues should work.
