# P2-AISUB R3.3 — Fresh new-film translation core (no expired R3.1 ZIP)

**Scope:** source-only, caller-supplied provider callbacks, local private filesystem. This is a **new schema**; it must not overwrite, import or silently claim compatibility with any R2/R3/R3.1 checkpoint, including the lost `full_srt_trial_r3.py` bundle. **No Gemini implementation or cloud call is built in.** G4 Signed Release remains `NOT_PLANNED`.

## Why

The original 1,761-cue Vietnamese film SRT is already present on the owner-controlled Windows host (real file SHA confirmed in Issue #89/88). Its English source file was not found in a small, explicitly bounded scope, so **do not translate that movie again or create fake EN-derived checkpoints**. This R3.3 source prepares an independent, checkpoint-preserving *future new-film* path. It uses the already accepted **R3.2 continuous queue** to avoid waiting for an entire batch wave.

## Contract

- `run_new_film(source_bytes, "srt"|"vtt", workdir, confirm="RUN_R33_NEW_FILM_V1", full_story_context=callback, translate_batch=callback, max_workers=1..4)` is for a future **private** adapter only. It is not available as a live-model CLI. The owner must separately approve transferring any new SRT to the selected model and identify the correct Antigravity Gemini 3.8 Flash High command/provider envelope first; no paid API or silent fallback.
- Defaults to **no model**: CLI accepts `--source` and `--workdir` **for inspection only**, and does not run a translator. It does not create a workdir in inspection mode.
- New workdir is marked with immutable `work/r33_manifest.json`, schema `torrent-tv-r33-new-film-v1`, exact SHA-256 of source SRT/VTT, cue count, 90-cue batch size, fixed model **policy label** `ANTIGRAVITY_GEMINI_3_8_FLASH_HIGH`, and the batch count. The label is **not provider identity attestation**; real adapter must verify and record actual model before calling.
- R3.3 uses its own `.r33_owner.lock` under `work/`, held by OS `msvcrt` (Windows) or `fcntl` (POSIX), from context invocation through batch scheduling, QA and final output. **This lock does not coordinate with unmodified R2/R3.1 processes**, so legacy paths are refused.
- Each new `work/batch_NNN.json` includes exact source SHA, model policy, batch ID, first/last cue and plain UTF-8 translations with a SHA-256 digest for accidental corruption detection. Each batch is committed with exclusive new-name hard-link from a synced temporary file and read back. Existing files are never overwritten. The digest is a **self-consistency check, not a tamper-proof signature/model attestation**.
- Resume checks manifest identity and all cached checkpoints **before** any callback. Only missing 90-cue batches may be dispatched. Strict key, order, text validation via the canonical `cue_pipeline.apply_translations` rejects missing/extra/corrupt translated cue. The original source timestamps are re-used, never generated by the provider.
- First observed provider or checkpoint error halts **new** dispatch with zero automatic retries, while already-in-flight batches finish and may commit valid results, as in R3.2. Verified checkpoint data is preserved for a later explicit continuation.
- Only after **all batches** verify does the core write a **new** private `translated.vi.srt`/`.vtt`; an existing output is verified against assembled bytes or rejected. The module never sends an APK or changes Redmi/OMP/TorrServer.
- Logs/return values contain only counts, source/output SHA and constant status values; no subtitle text, private paths, API key, raw provider response, magnet or film title. The workdir *contains private subtitle text* and must be kept outside this PUBLIC GitHub repository or public Actions artifacts.
